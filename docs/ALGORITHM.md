# 同作品身份识别算法

## 设计目标

本工具寻找两类结果：

1. 作品身份相同、但格式、分辨率、编码或文件大小不同的版本。
2. 文件大小和完整 MD5 都相同的字节级副本。

第一类的核心不是“整段文件名看起来相似”，而是先从名称中提取作品身份，再比较身份字段。任何明确冲突的日期、集号、作品编号、年份或分段都具有否决权，不能被共同前缀或较高字符相似度覆盖。两类结果都只作为候选，最终删除决定仍由用户作出。

## 扫描前过滤与比对范围

目录遍历阶段先应用用户设置，只有保留下来的文件才会创建作品身份、生成候选或读取 MD5：

1. 文件类型过滤：常见视频、自定义扩展名或全部普通文件。
2. 大小范围过滤：文件字节数小于最小值或大于非零最大值时跳过；`0` 表示对应限制关闭。
3. 排除目录过滤：用户列出的目录及其全部子目录不进入遍历。
4. 可选隐藏/系统项过滤：Windows 使用文件属性，同时兼容点号开头的隐藏名称。
5. 可选临时文件过滤：识别 `.part`、`.partial`、`.tmp`、`.crdownload`、`.download` 等未完成或临时后缀。
6. 文件名关键字过滤：使用 Unicode NFKC 与忽略大小写的包含判断，多个关键字之间是“任一命中即排除”。

比对范围在候选对层面生效，并同时传给作品身份与 MD5 通道：

- “全部文件”不增加位置限制。
- “不同所在目录”要求候选至少跨两个实际父目录。
- “同一所在目录”按父目录独立分桶，结果不会跨目录连接。
- “不同扫描根目录/盘符”要求候选来自两个分别加入的扫描根目录。

作品身份通道可以关闭，以便只做完整 MD5 确认；若 MD5 也关闭，界面会拒绝开始，因为此时没有任何有效比对方式。

## 名称预处理

对每个文件执行以下只读处理：

1. 去掉最后一个扩展名。
2. 使用 Unicode NFKC 统一全角/半角字符，忽略英文大小写，并用内置常用表生成繁简统一的匹配形式。
3. 删除分辨率、编码、片源、语言字幕、发布组和宣传标签，例如 `4K`、`1080P`、`BluRay`、`x265`、`国语中字`。
4. 删除网站域名和站点品牌，但不删除包装之后的未知字段。比如 `2048社区 - fun2048.com@fc1298546` 会保留 `fc1298546`，避免所有文件只剩下 `2048社区`。
5. 将确实作为续集标记的罗马数字 I–X 转为阿拉伯数字，同时保留 `I Robot` 这类普通标题。

只有遇到 `VTS_01_1.VOB`、`VIDEO_TS.VOB`、BDMV `STREAM/00001.M2TS` 等明确的光盘通用文件名时，程序才读取路径上下文。它会跳过 `VIDEO_TS`、`BDMV`、`STREAM`、`Disc1` 等容器目录，取最近的有效上级影片目录作为作品身份，并把通用文件名和光盘目录保留为分段标记。普通文件始终只解析自身文件名，避免目录名称无条件污染作品身份。

## 作品身份解析顺序

程序按强标识优先的顺序识别身份。

### 1. 日期单集

支持 `YY.MM.DD`、`YYYY.MM.DD`、使用横线/空格的等价格式，以及独立的 `YYYYMMDD`。日期会进行真实日历校验。

例如：

- `brothalovers.15.07.28.lynna.nilsson`
- `brothalovers.2015.07.28.lynna.nilsson.4K`

两者解析为系列 `brothalovers`、日期 `2015-07-28`、单集标题 `lynna nilsson`，属于同一作品。`brothalovers.15.04.02.rachel.rayye` 的日期不同，因此直接隔离，即使系列前缀完全相同也不会得到置信度。

同一系列和日期下，单集标题相同、词序变化或仅有轻微逐词拼写差异时可以匹配；出现不同人物名或其他实质词语时拒绝匹配。

### 2. 系列连续编号

支持 `fellatiojapan567` 这类“较长系列名 + 连续数字”，以及 `Japanese amateur leak (12)` 这类括号单集编号。广告域名 `www.98T.la@` 会先删除，再分别保留系列名和具体编号。系列相同但编号不同直接隔离；四位的 1900–2099 不按此规则处理，以免把 `BladeRunner2049` 误当成系列单集。

### 3. 季集编号

支持 `S02E07`、`Season 2 Episode 7`、`2x07`、`E07`、`EP07`、`Episode 7` 和 `第12集`。身份键由系列名称和规范化集号共同组成。不同季或不同集直接隔离。

### 4. 作品编号

支持常规及字母数字混合前缀，如 `MIDA-630`、`S2MBD-001`，以及 FC2、1PONDO、10MUSUME、Caribbeancom、Tokyo-Hot 等特殊形式。

- 编号相同：置信度 100%。
- 编号不同：置信度 0%，不再用模糊标题强行合并。
- 数字部分去掉前导零，因此 `ABC-001` 与 `ABC-1` 使用同一身份键。

四位电影年份和 `1080P/2160P` 等画质数字会被排除，避免误识别成作品编号。`VD-1080`、`HD-720`、`FHD-1080` 等组合明确属于画质标签，不得成为编号或作品标题。点号或空格后的短数字优先按日期/集号理解，只有明确连字符等可靠结构才作为短番号。

### 5. 普通影视标题

没有结构化身份时，程序生成清理后的影视标题、词语列表、无年份别名和“第一部”安全别名：

- `寒战1` 可以和 `寒战` 匹配；`寒战2` 不会删除尾号。
- `流浪地球.2019` 可以和 `流浪地球` 匹配。
- 两侧都写明年份且年份不同则隔离同名翻拍作品。
- `2001 A Space Odyssey 1968` 把最后的 `1968` 作为年份，并保留片名中的 `2001`。
- `1917`、`1984` 等四位数字标题保留；`015`、`032`、`230` 等缺少系列名称的短纯数字证据不足，不单独形成标题候选。
- `ck` 等 1–3 位纯 ASCII 碎片证据不足，不参与名称候选；字节完全相同的文件仍可由 MD5 通道发现。

普通标题的匹配优先级为：

1. 清理后标题或安全别名完全相同。
2. 至少两个实质词语的集合相同，仅排列顺序不同。
3. 词数相同，且每一个不同词都能与另一侧的词形成高相似拼写对应，再计算整体字符序列与二元字符集合分数。

第三条只用于容忍轻微拼写错误。共享一个很长的系列前缀、但人物名或单集名不同，会在逐词检查时被拒绝，不能因为整串字符仍然接近而合并。

三个界面模式对应的最低分数为：

| 模式 | 阈值 | 用途 |
| --- | ---: | --- |
| 严格作品识别（推荐） | 0.92 | 优先减少误报 |
| 标准作品识别 | 0.89 | 允许少量标题拼写变化 |
| 兼容轻微拼写差异 | 0.86 | 提高拼写变体召回率，仍保留全部强冲突保护 |

## 分段保护

程序识别 `CD1/CD2`、`Disc1/Disc2`、`Part1/Part2`、`Pt1/Pt2`、部分中文上下集标记、番号后的独立数字段号和 `A/B` 段。若番号后先出现很长的说明文字，末尾明确的 `_1/_2/_3/_4` 仍作为分段，而不是被说明文字遮住。

`KAVR-253-2` 和 `KAVR-253-8` 的番号同为 `KAVR-253`，但分别是第 2 段和第 8 段。两者内容互补，不是可互删副本，因此返回不匹配。一个文件有分段、另一个没有分段时也不自动合并。`MIDA-630-C` 中的 `C` 仍作为常见版本标签处理，可与 `MIDA-630` 匹配。

## 候选生成与进度

为了控制大目录的比较量，程序通过作品编号、精确身份别名、实质词语、二元字符块和排序邻域生成候选对，不对数万文件做无差别两两比较。初步连通分量还会围绕锚点再次拆分，抑制传递性误合并。

界面依次显示“解析作品身份”“生成同作品候选”“核对作品身份”“整理同作品候选组”。每个阶段报告实际总量、已完成、剩余、速度、已用时间和预计剩余时间，并限制刷新频率，避免进度显示本身拖慢扫描。

## MD5 完全重复通道

程序首先按文件大小分桶，只有同一大小至少出现两个文件时才进入哈希通道，唯一大小文件不会进行内容读取。用户在开始扫描前选择模式：

| 模式 | 行为 |
| --- | --- |
| 关闭 | 跳过整个哈希通道，作品身份识别照常进行 |
| 智能（默认） | 先计算快速指纹，只有同大小且指纹相同的文件才计算完整 MD5 |
| 完整 | 对全部同大小候选计算或安全复用完整 MD5 |

模式在点击“开始扫描”时固定，之后自动运行到底，不会在目录扫描完成后再次弹窗等待确认。

大于 3 MB 的文件只读取开头、中间、结尾各 1 MB，并用 BLAKE2b 生成快速指纹；小文件在这一步已经覆盖全部内容，因此同时完成 MD5。快速指纹只是高效预筛，最终完全重复候选仍要求文件大小和完整 MD5 同时相同。

程序缓存路径、大小、纳秒时间状态、快速指纹和 MD5。缓存命中并不直接作为结果：每次仍重新读取三段快速指纹，只有文件状态和新指纹都一致才复用完整 MD5。缓存最多保留 20,000 条并自动淘汰较旧记录。

智能模式不会把作品名称相同作为 MD5 前提，因此仍可发现名称完全不同的字节副本。大小和 MD5 都一致的文件组成强候选组。合并两个通道时，每个精确 MD5 组是独立的内容边界：一个名称组只与一个 MD5 组重叠时，可以补入同作品的不同编码版本；若同时碰到两个或更多不同 MD5 组，则绝不把这些 MD5 组传递串联成大组，只保留各自独立的精确重复结果。这样同时保证一个文件只出现一次，并阻断弱名称规则造成的桥接误合并。计算前后都会检查大小和修改时间，文件在哈希过程中发生变化时，本次结果会被丢弃并产生警告。

## 视频信息安全辅助

若存在外置 ffprobe，软件读取候选视频的分辨率、时长和编码。同 MD5 文件只解析一次，其余记录共享元数据。

- 片长差不超过 1%（并保留 8 秒容差）时显示“视频时长接近”。
- 片长差超过 3% 且超过 30 秒时进入重点复核状态，智能选择只建议保留项，不自动标记任何删除项。
- 完整 MD5 相同的纯哈希组不需要片长保护，因为内容字节已经相同。

候选组和组内文件的所有列都可排序。大小、时长、分辨率和修改时间使用底层数值而不是显示字符串，未知元数据固定置于末尾。候选组显示精确 MD5 子组数量；每个文件显示“MD5 相同 ×N”“MD5 已验证但组内不同”“快速指纹不同”或“作品身份相似、内容未确认”。两张表的列顺序都可自定义并持久保存。

## 智能保留排序

顺序为：

1. 实际视频像素；没有 ffprobe 时使用文件名画质标签估算。
2. 实际元数据比推测信息优先。
3. 常见现代封装格式优先级。
4. 文件大小作为最后的平局条件。

这只是建议，不表示质量的绝对结论。片长、剪辑、音轨、字幕和内容完整性仍需人工播放确认。
