# 相似作品识别算法

## 设计目标

本工具同时寻找“同一作品的不同文件版本”和“文件大小、完整 MD5 均相同的副本”。两类结果都以候选组呈现，删除决定仍由用户作出。

## 名称归一化

对每个文件执行以下只读处理：

1. 去掉最后一个扩展名。
2. 使用 Unicode NFKC 统一全角/半角字符，忽略英文大小写，并用内置常用表生成繁简统一的匹配形式。
3. 提取强标识：
   - 常规及字母数字混合前缀，如 `MIDA-630`、`S2MBD-001`。
   - 特殊形式：FC2、1PONDO、10MUSUME、Caribbeancom、Tokyo-Hot。
4. 清理网站域名、`@发布组`、常见发布组名、括号和分隔符。
5. 移除分辨率、编码、片源、复合字幕语言和宣传标签。
6. 将作为续集标记的罗马数字 I–X 转为阿拉伯数字（包括其后还有年份/画质标签的情况），同时保留 `I Robot` 这类普通标题，并生成英文词语列表。
7. 标题紧凑化后生成主键、无年份别名和第一部别名。

## 特殊规则

### 第一部别名

普通标题若以 `1` 或 `01` 结尾，且前面至少有两个字符，会额外生成去掉尾号的别名。因此 `寒战1` 可以和 `寒战` 匹配。`寒战2` 不会去掉数字，避免把第二部并入第一部。

### 年份保护

一侧写有发行年份、另一侧没有时，可以通过无年份别名进入同一候选组。例如 `流浪地球.2019` 与 `流浪地球`。两侧都写明年份且年份不同时直接拒绝匹配，避免把同名翻拍电影合并。

当一个名称中出现多个年份范围数字时，优先把最后一个视为发行年份，因此 `2001 A Space Odyssey 1968` 会保留片名中的 `2001`。只有一个且位于名称开头的无括号数字（如 `1917`）默认按片名处理，减少数字片名误判。

### 分段保护

识别 `CD1/CD2`、`Disc1/Disc2`、`Part1/Part2`、`Pt1/Pt2` 及部分中文分段标记。不同分段直接返回不匹配；一个有分段、另一个没有分段时也不自动合并。这样宁可少报，也不把互补的上下集当成可以删除的副本。

### 作品编号保护

两个文件都存在编号时：

- 编号相同：置信度 100%。
- 编号不同：置信度 0%，不再用模糊标题强行合并。

四位电影年份和 `1080P/2160P` 等画质数字会被排除，避免误识别成作品编号。

番号的数字部分会去除前导零，因此 `ABC-001` 和 `ABC-1` 使用同一匹配键，但界面仍展示原始文件名。

## 模糊相似度

普通标题的分数由三部分构成：

- 字符序列相似度：68%。
- 二元字符集合 Jaccard 相似度：32%。
- 当一个有效标题完整包含另一个且短标题不少于 3 个字符时，应用包含关系下限。
- 英文标题拥有至少两个有效词时，增加与排列顺序无关的词集合比较。

三个预设阈值：

| 模式 | 阈值 | 用途 |
| --- | ---: | --- |
| 保守 | 0.90 | 优先减少误报 |
| 标准 | 0.84 | 默认平衡 |
| 宽松 | 0.76 | 优先召回，要求人工细查 |

为了控制大目录的比较量，候选对通过作品编号、精确别名、二元字符块和排序邻域生成，不对数万文件做无差别两两比较。初步连通分量还会围绕较短标题锚点再次拆分，抑制传递性误合并。

## MD5 完全重复通道

程序首先按文件大小分桶，只有同一大小至少出现两个文件时才进入哈希通道，唯一大小文件不会进行内容读取。用户可以选择三种模式：

| 模式 | 行为 |
| --- | --- |
| 关闭 | 跳过整个哈希通道，文件名识别照常进行 |
| 智能（默认） | 先计算快速指纹，只有同大小且指纹相同的文件才计算完整 MD5 |
| 完整 | 对全部同大小候选计算或安全复用完整 MD5 |

大于 3 MB 的文件只读取开头、中间、结尾各 1 MB，并用 BLAKE2b 生成快速指纹；小文件在这一步已经覆盖全部内容，因此同时完成 MD5，避免二次读取。快速指纹只是高效预筛，最终的完全重复候选仍要求文件大小和完整 MD5 同时相同。

程序会缓存路径、大小、纳秒时间状态、快速指纹和 MD5。缓存命中并不直接作为结果：每次仍重新读取三段快速指纹，只有文件状态和新指纹都一致才复用完整 MD5。缓存最多保留 20,000 条并自动淘汰较旧记录。

智能模式不会把“文件名高度相似”作为 MD5 前提，因此仍可发现文件名完全不同的字节副本。相反，同一作品的不同编码通常大小和 MD5 都不同，继续由文件名、时长和分辨率通道判断。

当同大小候选的完整读取上限达到 20 GB 时，界面先显示快速读取量、完整读取上限和按常见磁盘速度估算的时间区间。用户可以继续、只跳过本次 MD5 或停止整个扫描。哈希进度按实际读取字节计算，每 0.25 秒以内合并更新，避免大量界面事件影响速度。

大小和 MD5 都一致的文件组成强候选组；如果它与文件名候选组重叠，两个结果会合并，确保一个文件只出现一次。

计算前后都会检查大小和修改时间。文件在哈希过程中发生变化时，本次结果会被丢弃并产生警告。

## 视频信息安全辅助

若存在外置 ffprobe，软件读取候选视频的分辨率、时长和编码。同 MD5 文件只解析一次，其余记录共享元数据。片长接近会显示为辅助证据；片长相差超过 12% 且超过 5 分钟时，候选组进入重点复核状态，智能选择不会自动标记删除项。

## 智能保留排序

顺序为：

1. 实际视频像素；没有 ffprobe 时使用文件名画质标签估算。
2. 实际元数据比推测信息优先。
3. 常见现代封装格式优先级。
4. 文件大小作为最后的平局条件。

这只是建议，不表示质量的绝对结论。片长、剪辑、音轨、字幕和内容完整性仍需人工播放确认。
